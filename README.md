# ShortsBattle

ShortsBattle is an online multiplayer game built as a **Telegram Mini App**. Players are matched into a game round, given a theme (e.g. "Find a video with an orange cat"), and race to submit a short video clip that best matches it. Once submissions are in, players watch and vote on each other's videos, and points are awarded based on likes/dislikes. Games are played and administered entirely through Telegram — the bot handles onboarding and notifications, while the Mini App (a Vue web app opened inside Telegram) is the actual game UI.

## How a game works

1. A player opens the Mini App from the Telegram bot and joins a game for a theme.
2. Once enough players join, the game moves through staged phases (lobby → submit → watch/vote → result), each with its own time limit.
3. Players submit a short video for the current theme.
4. All submitted videos are shown to the group, and players vote (like/dislike) on each other's submissions.
5. Points are tallied from votes and a result is shown at the end of the round.

Game state transitions are time-boxed (see `GameConfig` in `cmd/server/main.go`) and are advanced automatically by a background watchdog even if no player is actively interacting with the app.

## Architecture

The project is split into a Go backend (game server) and a Vue frontend (the Telegram Mini App).

```
cmd/server        entrypoint (main.go) — wires everything together and starts the HTTP/WebSocket server
internal/api      Echo HTTP handlers (REST API consumed by the Mini App)
internal/bot      Telegram bot (onboarding, notifications, deep links into the Mini App)
internal/ws       Real-time layer built on Centrifuge (game state push updates over WebSocket)
internal/services games/themes/videos/players/auth business logic
internal/watchdog background workers (asynq) that advance game stages on a schedule and react to DB status changes
internal/db       Postgres (pgx) connection management, Redis client, sqlc-generated query code (internal/db/qg)
internal/models   shared request/response and domain types
db/migrations     Goose SQL migrations (source of truth for the schema)
db/queries        Hand-written SQL used to generate internal/db/qg via sqlc
web-app           Vue 3 + TypeScript Telegram Mini App (Vite, Pinia, Tailwind, Centrifuge client)
```

Key building blocks:

- **HTTP API** (`internal/api`) — Echo-based REST API, JWT-authenticated (`Authorization: Bearer <token>`), used by the Mini App for actions like joining a game, submitting a video, voting, and fetching themes/results.
- **Real-time updates** (`internal/ws`) — a Centrifuge node pushes game state changes (stage transitions, new submissions, votes) to connected clients over WebSocket.
- **Telegram bot** (`internal/bot`) — built with `go-telegram/bot`; issues the JWT used by the Mini App and links players to their Telegram account.
- **Game watchdog** (`internal/watchdog`) — an `asynq` (Redis-backed) task queue that advances games to their next stage once a stage's timer expires, plus a Postgres `LISTEN/NOTIFY`-based watchdog that reacts immediately to relevant DB status changes.
- **Persistence** — Postgres accessed via `pgx`/`pgxpool`, with queries generated by `sqlc` from `db/queries/*.sql` into `internal/db/qg`. Redis is used for caching (player service) and as the `asynq` broker.

## Useful commands

Backend (Go, run from repo root):

```bash
# run the game server locally (reads config from .env)
go run ./cmd/server

# run tests
go test ./...

# apply DB migrations (goose migration format, files live in db/migrations)
goose -dir db/migrations postgres "$DATABASE_URL" up

# create a new migration
goose -dir db/migrations create <migration_name> sql

# regenerate internal/db/qg from db/queries/*.sql after changing queries or schema
sqlc generate
```

Frontend (Vue Mini App, run from `web-app/`):

```bash
npm install       # install dependencies
npm run dev        # start the Vite dev server
npm run build      # type-check (vue-tsc) and build for production
npm run preview    # preview the production build locally
```

Configuration is provided via a `.env` file at the repo root (see `.env_tmp` for the required keys: `JWK_KEY_SECRET`, `TELEGRAM_BOT_KEY`, `TELEGRAM_BOT_WEB_APP_URL`, `DATABASE_URL`, `REDIS_HOST`, `ENV`).
